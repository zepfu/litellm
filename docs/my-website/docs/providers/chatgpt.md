# ChatGPT Subscription

Use ChatGPT Pro/Max subscription models through LiteLLM with OAuth device flow authentication.

| Property | Details |
|-------|-------|
| Description | ChatGPT subscription access (Codex + GPT-5.3/5.4 family) via ChatGPT backend API |
| Provider Route on LiteLLM | `chatgpt/` |
| Supported Endpoints | `/responses`, `/chat/completions` (bridged to Responses for supported models) |
| API Reference | https://chatgpt.com |

ChatGPT subscription access is native to the Responses API. Chat Completions requests are bridged to Responses for supported models (for example `chatgpt/gpt-5.4`).

Notes:
- The ChatGPT subscription backend rejects token limit fields (`max_tokens`, `max_output_tokens`, `max_completion_tokens`) and `metadata`. LiteLLM strips these fields for this provider.
- `/v1/chat/completions` honors `stream`. When `stream` is false (default), LiteLLM aggregates the Responses stream into a single JSON response.

## Authentication

ChatGPT subscription access uses an OAuth device code flow:

1. LiteLLM prints a device code and verification URL
2. Open the URL, sign in, and enter the code
3. Tokens are stored locally for reuse

## Usage - LiteLLM Python SDK

### Responses (recommended for Codex models)

```python showLineNumbers title="ChatGPT Responses"
import litellm

response = litellm.responses(
    model="chatgpt/gpt-5.3-codex",
    input="Write a Python hello world"
)

print(response)
```

### Chat Completions (bridged to Responses)

```python showLineNumbers title="ChatGPT Chat Completions"
import litellm

response = litellm.completion(
    model="chatgpt/gpt-5.4",
    messages=[{"role": "user", "content": "Write a Python hello world"}]
)

print(response)
```

## Configuration

### Native Codex automatic review

On the direct Codex OAuth Responses route, `codex-auto-review` uses the native
model without an alias. Its trusted model capability,
`codex_oauth_ordinary_quota_exempt`, makes ordinary Codex allowance inapplicable
to charging and weekly account balancing. Auto-review consumes no ordinary
quota, but an exhausted account can still reject it. Account availability is
checked separately from charging so the inventory can select another account.
Reviewer refusals do not imply ordinary quota exhaustion. Explicit provider
quota headers are still recorded.

The active model map must include this capability. The bundled map includes it;
`LITELLM_LOCAL_MODEL_COST_MAP=True` selects that map.

The route preserves a received `x-openai-subagent` header and body
`client_metadata`, while inventory-selected credentials remain authoritative.
Authentication, session ownership, and actual provider rejections still apply.
This direct-route header handling requires a bound account selection. Alias
requests such as `basic` and `work` keep their existing alias dispatch and do
not bind a direct account at the outer Responses route.
If a provider confirms account exhaustion before output is committed, the
direct route can use its existing bounded account-failover path to retry with
another eligible inventory account. Credential binding, ownership, replay
safety and the provider-call budget still apply. Unknown failures and committed
output do not acquire retry permission from the quota exemption.

The exemption does not approve commands; Codex's built-in reviewer still makes
the approval decision. Local admission does not guarantee provider availability.

### Environment Variables

- `CHATGPT_TOKEN_DIR`: Custom token storage directory
- `CHATGPT_AUTH_FILE`: Auth file name (default: `auth.json`)
- `CHATGPT_API_BASE`: Override API base (default: `https://chatgpt.com/backend-api/codex`)
- `OPENAI_CHATGPT_API_BASE`: Alias for `CHATGPT_API_BASE`
- `CHATGPT_ORIGINATOR`: Override the `originator` header value
- `CHATGPT_USER_AGENT`: Override the `User-Agent` header value
- `CHATGPT_USER_AGENT_SUFFIX`: Optional suffix appended to the `User-Agent` header
